## 4. Gemma planning, before and after (`evaluation/planner_check.py`, 19 cases, real Gemma 4 E2B)

The acceptance criteria are those of the earlier runs, with two differences:

- a direction counts if the vector is within 30°;
- "move your hand to the left" counts if Gemma gives an empty plan or names any unimplemented operation, but not
  `look`.

| Version | Correct | Valid JSON | Tabletop | Embodied |
|---|---|---|---|---|
| before cleanup (`6e56980`: templates, word directions) | 9/19 | 18/19 | 5/12 | 4/7 |
| after cleanup, first prompt wording | 2/19 | 11/19 | 2/12 | 0/7 |
| after cleanup, nested arguments accepted (JSON shape) | **6/19** | **19/19** | 3/12 | 3/7 |

Raw answers are in `out/eval/embodiment/planner_cleanup.json` (`gemma_raw` per case).

**What changed:**

- **Gemma's reasoning was mostly right.** The first drop came from an output-format problem. The new wording ("its
  own arguments") made Gemma nest the arguments under an `"arguments"` key. Accepting both shapes fixed it, and
  JSON validity is now the best measured (19/19).
- **Now correct that was not:** "Look at the red cube." → `inspect`.
- **Now wrong:**
  - "Look down at the floor." and "Look behind you." got `[0, 0, 1]` (up). The removed word vocabulary used to hide
    this vector sign error;
  - "Where is the red cube?" and "Find the banana." got `observe` / `locate` without the other step;
  - "What objects do you see?" got `observe` with no `describe_scene`.
- **Unchanged and wrong:**
  - every pick-and-place request is planned as `pick` + `pick_place`. This was wrong before too. It now fails at
    run time, with no motion: `pick_place` of the held object is `infeasible`, and Gemma decides;
  - "Move your hand to the left." still becomes `look` along `[-1, 0, 0]`. Gemma conflates the hand with the
    camera, and nothing in the software can tell.

## 5. Functionality changed or temporarily unavailable

- **Pronouns.** "It" is no longer bound by Python. Gemma must use the `#id` from the context. If Gemma writes "it",
  resolution treats it like any other description: the step fails or asks, and Gemma decides.
- **Clarification answers.** Only numbers, or an empty line, are accepted. "the gold one", "nearest" and "cancel"
  are asked again.
- **Resolution accuracy.** The lexical cross-check and the comparison step, which used to catch some wrong Gemma
  picks, are gone. Gemma's crop confirmation still runs. Wrong-object picks that the cross-check caught may now
  pass to the confirmation.
- **Objective protection.** A re-plan can drop the user's objective (strict xfail).
- **Automatic follow-ups.** There is no "not visible → explore" or "uncertain → closer look" rule. Both depend on
  Gemma's decision, which is not yet measured live.
- **`look`.** It needs a correct vector from Gemma; sign errors were observed for down and backward.
